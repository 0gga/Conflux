# Source, architecture and coverage audit

Owner direction, 25 October 2026: continue implementing the backlog, record issues found along the way, follow SOLID more rigorously, review appropriate patterns, audit 100% of non-UI code first, then 100% of UI code. Full measured test coverage remains the target. Neither a file review nor a passing test suite establishes that target.

`CODE_AUDIT.json` is the exhaustive file-review ledger. `scripts/coverage_audit.py` discovers every `.cpp`, `.h`, `.qml` and `.js` below the application's `src/` and `qml/` roots. New files begin pending. A reviewed entry needs the current source hash, its assigned phase, and actual checks. Changed sources become stale; synchronizing the ledger never approves them. Removed/renamed entries must be reconciled explicitly.

The first phase includes domain policies, application workflows, models, provider adapters and persistence. Models with QObject properties are included: the absence of pixels is not an excuse to skip their state machines. The second phase covers QML/JavaScript, theme/presentation helpers, native window/input adapters and application composition. The embedded smoke-test implementation has its own verification phase; it is visible in the inventory and is not misrepresented as shipped business behavior. Tests, scripts, CMake, generated code and vendored dependencies are outside application C++ percentages; changes to our verification tools receive their own regression tests.

The ledger records source review, not a claim that every possible state works. For each responsibility inspect contracts, ownership/lifetimes, stale and duplicate asynchronous delivery, reentrancy, error boundaries, deterministic identities, compatibility, atomic writes, external changes, resource bounds and test evidence. Link concrete gaps to the backlog. Keep findings distinct from confirmed failures.

## Measurement

GCC measurements retain C++ executable-line, function and branch counts separately. Aggregates are weighted by counters, never averages of per-file percentages. Missing implementation records are listed, not dropped from the audit. Headers without compiler counters stay explicitly unmeasured; declaration-only headers do not acquire invented executable lines. A threshold cannot pass with an unmeasured implementation or stale/missing source snapshot. Qt-generated/compiler branches retain the documented gcovr exclusions; do not add business-code exclusions to achieve a percentage.

QML/JavaScript line coverage is not supplied by GCC. It remains explicitly unmeasured. Rendered interaction, keyboard, geometry, scale, scroll and pixel evidence is separate. A UI threshold cannot silently call QML covered based on C++ results. Complete the non-UI phase before beginning the exhaustive UI review.

## Design decisions

Use existing narrow ports, codec strategies, independent diagnostic rules, immutable command intents and the composition root. Extract a responsibility when it has an independent policy, lifecycle or failure boundary. Add an interface when a consumer needs a genuinely narrower contract or an independently replaceable adapter. Adding factories, repositories, event buses or inheritance solely to rename existing calls is not a SOLID improvement.

The first confirmed audit findings are queue notification lifetime, root-array JSON field addressing and the world-handoff read limit. The audit also identified an unindexed reconciliation fallback, worker exception boundaries, provider-qualified diagnostics, stale weak registry entries, and instrumented/performance-test separation as follow-up candidates. Each has concrete acceptance criteria in `BACKLOG.md`. The remaining ledger entries stay pending until inspected; this audit is in progress.
